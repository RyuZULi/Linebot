## ★ F4. 同事按了選項，助手卻說「選項已過期」

### 現象
- 為了方便一起測試，把兩位同事拉進同一個 LINE 群組使用 CEC_API助手。
- 同事 A 說某個功能「壞掉了」，助手回問「發生什麼狀況？」並列出選項按鈕。
- 同事 B 按了其中一個選項，助手回：「剛才的選項已經過期了，麻煩再描述一次遇到的狀況。」
- B 只好照著清單把選項文字一字一字打出來，其中一句「鋼構、機電、連結檔有算嗎？」因為含「機電」，
  還被誤判成機電 API 的問題，轉介給機電窗口。

### 原因
- 程式用「**發言的那個人**」來記對話狀態（目前在聊哪個按鈕、回問了哪些選項）。
- 一對一聊天時，發言的人＝這段對話，沒有問題；但在群組裡，大家看到的是**同一串對話、同一組按鈕**。
- B 按的是 A 收到的選項，程式去找 B 的紀錄，當然什麼都沒有 → 判斷成「過期」。

### 怎麼查出來的
- 問答紀錄裡沒有「過期」那一筆：當時過期的分支直接回覆，沒有寫進紀錄。
- 改對照伺服器的請求時間：09:49:01 助手給 A 選項 → 09:49:21 有一筆請求沒有對應的紀錄 →
  09:49:28 一個**從沒跟助手說過話的帳號（B）**，打出了 A 的選項 1 原文。
- 一開始猜錯了方向（以為是電腦版 LINE 看不到按鈕），使用者補充「兩位都用電腦版，而且按得到」之後，
  才對出「另一個帳號看得到 A 的選項」→ 兩人在同一個群組。

### 修法
1. 對話狀態改以「**聊天室**」為單位：群組用群組 ID、一對一用個人 ID。
2. 順帶修正測試中發現的其他問題：
   - 回問訊息本文列出編號，可以直接輸入編號或照打選項原文（同仁真的會照清單打字）。
   - 點過一個選項後，其他選項不會立刻失效。
   - 問題幾乎就是本庫常見問題原文時（相似度 ≥ 0.90），不再因為含「機電」被轉介。
   - 過期、重設等路線也寫進問答紀錄，下次出問題查得到。
3. **使用規範**：CEC_API助手設計上就是**一對一**使用。群組裡互相問，LINE 上的對話紀錄太亂，
   之後不會在群組使用；群組支援只是修 bug 的副作用，不再為群組情境加功能。

### 學到
- **測試情境本身也會造成 bug**：只是為了方便拉同事進群組，就碰到了設計時沒想過的使用方式。
  但也因此提早發現「狀態跟著人走，還是跟著對話走」這個設計假設。
- **紀錄要涵蓋所有路線**：「沒寫進紀錄」的分支出事時最難查；這次是靠伺服器請求時間反推出來的。
- **先問清楚使用者的環境，再下結論**：第一次的推測（電腦版看不到按鈕）跟實際情況不符，
  使用者一句補充就推翻了。跟 F1-2「先釐清狀況再回答」是同一個道理——這次是開發者自己也要做到。
